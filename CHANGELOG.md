deevy's user-visible changes, one entry per release. Each entry is folded from the changesets a pull request

A release is two Docker images and one `vX.Y.Z` tag — see [docs/OPERATIONS.md](./docs/OPERATIONS.md).

## 0.12.0

### Minor Changes

- **adapters, server** — [#194](https://github.com/WeAreNendo/deevy/pull/194) [`6029a77`](https://github.com/WeAreNendo/deevy/commit/6029a77ed63bfa3a2ca733afe69589c4fd5aa9ff) Thanks [@mattallty](https://github.com/mattallty)! - The Docker image no longer needs its volume given to uid 65532 before it starts. It starts as root, gives `/data` to 65532 when it isn't 65532's already, then runs deevy as 65532 for good, before it loads anything else. A host directory works whoever made it, and ends up belonging to 65532; a volume an older release wrote as root, or a database you restored from a backup, is taken over on the next start. Only the directory and the database's own files are changed, so the `chown` steps are gone from the docs. To keep deevy from ever starting as root, run it with `--user 65532:65532` (`runAsUser: 65532` and `fsGroup: 65532` on Kubernetes), as before: it then changes nothing, and refuses a `/data` it cannot write with the command that fixes it. A Kubernetes pod that sets `runAsNonRoot: true` must now also set `runAsUser`, and a container that drops every capability needs `--user` or `CHOWN`, `SETUID` and `SETGID` back.

### Patch Changes

- **core, web, server** — [#203](https://github.com/WeAreNendo/deevy/pull/203) [`2962596`](https://github.com/WeAreNendo/deevy/commit/2962596a53c759162f3fd98600775ca54d52d1e4) Thanks [@mattallty](https://github.com/mattallty)! - deevy no longer runs without `BETTER_AUTH_SECRET`. Unset, Better Auth fell back to a default secret it publishes: the Docker image then came up and answered `/healthz` while every sign-in failed, and a Worker signed everybody in on that published value without saying so, which left its sessions, the links it sent and the sign-in providers' tokens it sealed open to anyone who looked the value up. Now the Node server refuses to start and says which variable to set, and a Worker answers its API, `/healthz` included, with a 503 that says the same (its pages still load, and then can't reach it), and runs no Cron pass or queue message until it is set. If your Worker ran without one, set it with `wrangler secret put BETTER_AUTH_SECRET` (generate it with `openssl rand -base64 32`); that is a change of secret like any other, so everybody signs in again. The Node server also refuses `BETTER_AUTH_SECRETS`, Better Auth's own list of rotated secrets, which it read ahead of deevy's: unset it, and keep the current secret in `BETTER_AUTH_SECRET`.

- **agent** — [#208](https://github.com/WeAreNendo/deevy/pull/208) [`c86532a`](https://github.com/WeAreNendo/deevy/commit/c86532a31d3002fc7b3dc235f2ee2fa599bc71cd) Thanks [@mattallty](https://github.com/mattallty)! - Security: the reference runtime no longer runs git as root in a Run's clone.
