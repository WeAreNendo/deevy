deevy no longer wakes an Agent on a schedule. The **Schedule** column on **Settings › Agents** and the **Schedule** section on an Agent's page are gone. `agents.update` (`PATCH /api/agents/{memberId}`, `deevy agents update`) no longer takes `scheduleMinutes`, and the `--schedule-minutes` flag is gone. The field is ignored if you send it. An Agent no longer carries `scheduleMinutes`, and no Run starts with the trigger `schedule`. The sweep no longer looks for scheduled work. A Run starts when a record is routed to an Agent, when a comment mentions it, when the last sub-issue of a record routed to it closes, when it is tried again, or when the Agent starts one itself with `runs.start`. An Agent that should look again every so often now needs a timer of its own that calls `runs.start`.

An Agent splits work by opening sub-issues in your tracker with its own access, labelled for the Agent that should do each one, and deevy routes each one like any other record. Of the three numbers under **Settings › General**, only **Levels deep** is left, now titled **How deep sub-issues may go**. It is 3 by default and at most 20, and it now bounds something again. A sub-issue nested deeper than that is still taken from your tracker and shown, but it is routed to no Agent, by label, by the Project's default or by the tool's assignment. Its history gets one `delegation.refused` Event with `limit: "depth"`, the depth `allowed`, and `to`, the Agent it would have gone to. A mention of an Agent on such a record still reaches that Agent's inbox, but it opens no Run, and each time it says so with the same Event. `runs.start` on such a record now answers `FORBIDDEN` with the depth allowed, and when a parent's sub-issues all finish, a parent past the ceiling wakes no Agent. GitHub opens an issue before it makes it a sub-issue, so its Run can open before deevy knows how deep it is. When the link arrives, deevy now takes the record back from its Agent. It fails the Run if the Agent hasn't begun it, with the reason as the summary, so its Sponsor hears it failed. A Run already under way carries on. An Agent that links a sub-issue before labelling it is never routed in the first place. Raise the number and the next delivery of the record routes it. `workspace.update` (`PATCH /api/workspace`, `deevy workspace update`) takes only `name` and `maxDelegationDepth`. `maxChildrenPerIssue` and `maxOpenDescendants` are gone from the Workspace and from the operation, along with the `--max-children-per-issue` and `--max-open-descendants` flags.

The **Sub-issues** Notification is gone, from the Inbox, from **Settings › Notifications**, and from Slack and email routing. A Sponsor used to hear when an Agent's sub-issues all finished. Now the Run that wakes the Agent on the parent is that news, and the Sponsor hears when that Run finishes, as for any Run the Agent works for itself. A routing rule can no longer name `delegation`.
