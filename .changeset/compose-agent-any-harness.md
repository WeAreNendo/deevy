The Compose file's `agent` service now runs every runtime image, not only Claude Code's, and passes every setting the runtime reads. Set `DEEVY_AGENT_IMAGE` to `ghcr.io/wearenendo/deevy-agent:opencode`, `:cursor` or `:copilot` and give that image's credential (`CURSOR_API_KEY`, `COPILOT_GITHUB_TOKEN`, or the key for an OpenCode provider) in your environment or `.env`, and it reaches the container. Before, only `ANTHROPIC_API_KEY` did, and the service set `DEEVY_AGENT_HARNESS=claude-code` over the image's own, so every other image stopped at start looking for `claude`. `DEEVY_AGENT_EFFORT`, `DEEVY_AGENT_MAX_TURNS`, `DEEVY_AGENT_RUN_TIMEOUT_SECONDS`, `DEEVY_AGENT_PASS_ENV`, `DEEVY_AGENT_PORT`, `DEEVY_AGENT_WORKDIR` and the session's uid and gid used to do nothing under Compose and now take effect; the variables you name in `DEEVY_AGENT_PASS_ENV` still need adding to the service's `environment` yourself. A setting you leave unset no longer reaches the container at all, so the runtime's own default stands. The service no longer sets `DEEVY_AGENT_HARNESS`, which the image sets: a `DEEVY_AGENT_HARNESS` set for Compose is no longer passed, so choose the image instead. The runtime's default model on OpenCode is now `anthropic/claude-opus-5`, since OpenCode takes `provider/model`: an OpenCode runtime with no `DEEVY_AGENT_MODEL` used to fail every Run. An empty `DEEVY_AGENT_MODEL`, `DEEVY_AGENT_BASE_BRANCH`, `DEEVY_AGENT_SESSION_UID` or `DEEVY_AGENT_SESSION_GID` now counts as unset; an empty session uid used to run the coding agent as the runtime's own user.
