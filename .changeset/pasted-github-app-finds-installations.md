A GitHub App you connect with **Paste an App you already have** now offers the repositories it was already installed on. deevy used to learn where an App is installed only from GitHub's redirect after installing it, or from the delivery GitHub sends when an installation changes, so an App installed before it was pasted listed no repository to bind a Project to until somebody changed one of its installations, and then only that one. Binding a Project now asks GitHub where the App is installed every time, so its list of repositories is right whatever the Socket has recorded; only when GitHub cannot be asked does it fall back on what the Socket has. Connecting also asks GitHub, and the Socket's page lists each account under **Where it is installed**, leaving out any installation GitHub has suspended. It also keeps the App's own page on GitHub, so a pasted App's Socket page now has **Install it on more repositories** as one made from the manifest does. That link only ever goes to the page GitHub gave for the App, which on a GitHub Enterprise Server is the server's own; a Socket that has no such page shows no link rather than one to github.com. **Ask who deevy is there** on the Socket's page (`sockets.test`) asks GitHub again and keeps its answer, so an installation that was removed stops being listed. For a GitHub Socket pasted before this release, binding a Project offers every repository at once; the Socket's page catches up, with the App's page and every account it is installed on, when you choose **Ask who deevy is there**.
