**GitHub, through an App deevy writes for you.** Under **Settings › Sockets › Connect GitHub**, deevy posts the App's manifest to GitHub; GitHub makes the App and sends you on to install it, and deevy seals its credentials without anybody copying a key out of a browser. An App you already have can be pasted instead, its `.pem` whole.

A repository in one of the App's installations is a container. Binding a Project to one binds its issues and — unless you untick **Its code is here too** — its code, from the repository's own base branch. GitHub cannot assign an App, so a label is how a record is given to an Agent. A Human who signs in to deevy with GitHub rules from github.com with `/approve` or `/reject <why>`, with no linking step.

`DEEVY_GITHUB_API` points every GitHub Socket at a GitHub Enterprise Server. A Socket's page shows the address the App delivers to, and **Point GitHub at this address** moves the App there when the instance's address changed, as a laptop's tunnel does.

"Working in GitHub" in `docs/OPERATIONS.md` walks through it. It was walked end to end against github.com, with Claude Code as the Agent.
